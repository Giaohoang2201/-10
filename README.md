과제 10: 정렬 알고리즘의 성능 및 안정성 비교

선택 정렬, 버블 정렬(일반 / 조기 종료), 삽입 정렬(> / >=)을 직접 구현하고, 숫자 비교 횟수와 데이터 이동 횟수를 측정하여 성능과 안정성을 비교·분석하였다.

1. 파일 구성
파일	설명
sort_compare.c	전체 구현 (데이터 생성, 5가지 정렬, 횟수 측정, 안정성 검증)
result.txt	프로그램 실행 결과 원본
README.md	실험 방법·결과·분석 (이 문서)

실행 방법

gcc -O2 -o sort_compare sort_compare.c
./sort_compare > result.txt      # 약 40초 소요
2. 실험 방법
2.1 데이터와 측정 기준
데이터 1개 = (Key1, Key2) 두 정수(0 ~ 1,000,000, 서로 독립) + 원래 입력 순서 order(안정성 검증용, 정렬 기준 아님). 데이터 수 N = 10,000.
정렬 기준은 Key1만 사용하고, 오름차순으로 정렬한다. 라이브러리 정렬 함수는 사용하지 않았다. (qsort는 시험 입력을 준비하는 용도로만 사용했고, 측정에는 포함하지 않았다.)
비교 횟수: Key1끼리 비교할 때마다 1회. 반복문 인덱스·종료 조건 비교는 제외.
이동 횟수: 데이터 전체를 복사/대입할 때마다 1회. 교환(swap)은 3회. 삽입 정렬은 임시 변수 저장 1회 + 한 칸 이동마다 1회 + 최종 위치 대입 1회.
난수는 xorshift64*로 직접 생성(고정 시드)하여 재현 가능하게 하였고, 한 번 만든 원본 배열을 memcpy로 복사해 모든 알고리즘에 동일한 입력을 제공하였다.
선택 정렬은 최솟값이 이미 제자리에 있으면 교환을 생략한다(이동 0회).
2.2 구현한 알고리즘
선택 정렬
버블 정렬 (일반): 정해진 N-1번의 순회를 모두 수행
버블 정렬 (조기 종료): 한 순회에서 교환이 한 번도 없으면 종료
삽입 정렬 Case A: 이동 조건 data[j].key1 >  current.key1
삽입 정렬 Case B: 이동 조건 data[j].key1 >= current.key1

성능 비교(무작위 / 정렬 / 역순 / 부분 정렬)에서는 삽입 정렬은 안정 정렬인 Case A(>)를 대표로 사용하였다. (Case B의 평균 비교·이동 횟수는 무작위 실험에서 함께 측정하였고, Case A와 거의 같다.)

3. 무작위 데이터 100회 실험 결과

매 회 새 난수 데이터 10,000개를 만들고, 동일한 복사본으로 모든 정렬을 수행하였다. 100회 모두 Key1 오름차순 검증을 통과하였다.

알고리즘	총 비교 횟수	평균 비교 횟수	평균 이동 횟수
선택 정렬	4,999,500,000	49,995,000.0	29,970.5
버블 정렬	4,999,500,000	49,995,000.0	74,988,341.4
버블 정렬 (조기 종료)	4,998,444,038	49,984,440.4	74,988,341.4
삽입 정렬 (>)	2,500,610,404	25,006,104.0	25,016,111.8
삽입 정렬 (>=)	2,500,615,334	25,006,153.3	25,016,161.1
3.1 분석
선택 정렬의 비교 횟수는 입력과 무관하게 항상 N(N-1)/2 = 49,995,000회이다. 매 단계 남은 구간 전체를 훑어 최솟값을 찾기 때문이다. 실험값이 정확히 이 값과 일치한다.
일반 버블 정렬의 비교 횟수도 입력과 무관하게 49,995,000회로, 선택 정렬과 같다.
삽입 정렬의 비교 횟수는 약 N²/4 ≈ 25,000,000회로, 선택·버블의 약 절반이다. 삽입 정렬은 이미 정렬된 앞부분에서 자신의 위치를 찾으면 바로 멈추기 때문이다. 무작위 데이터의 평균 역전 쌍(inversion) 수가 N(N-1)/4 ≈ 25,000,000이고, 삽입 정렬의 이동 횟수는 역전 쌍 수 + 2(N-1)이므로 실험값(약 25,016,000)과 맞는다.
이동 횟수는 알고리즘 간 차이가 매우 크다.
선택 정렬은 교환을 최대 N-1번만 하므로 평균 약 29,970회(= 교환 약 9,990회 × 3)로 압도적으로 적다.
버블 정렬은 역전 쌍 하나를 해소할 때마다 교환 1번(이동 3회)이 필요하므로 약 3 × 25,000,000 ≈ 75,000,000회로 가장 많다.
삽입 정렬은 역전 쌍 하나당 이동 1회라서 버블의 약 1/3 수준이다.
따라서 데이터 쓰기 비용이 큰 상황에서는 선택 정렬이 유리하고, 비교 비용이 큰 상황에서는 삽입 정렬이 유리하다.
4. 버블 정렬의 조기 종료 효과
4.1 무작위 데이터 (100회)
일반 버블: 평균 49,995,000.0회, 조기 종료 버블: 평균 49,984,440.4회
차이는 평균 **10,559.6회(약 0.0211% 감소)**에 불과하다. 이동 횟수는 두 방식이 완전히 같다(교환 동작은 동일하므로).

무작위 데이터에서는 거의 마지막 순회 근처까지 교환이 계속 발생한다. 가장 작은 값이 맨 뒤쪽에 있으면 한 순회에 한 칸씩만 앞으로 이동하기 때문에, 필요한 순회 수가 N-1에 매우 가깝다. 그래서 조기 종료가 거의 도움이 되지 않는다.

4.2 입력 상태별 효과
입력	일반 버블 비교	조기 종료 버블 비교	감소율
무작위 (평균)	49,995,000	49,984,440	0.02%
이미 정렬	49,995,000	9,999	99.98%
역순 정렬	49,995,000	49,995,000	0%
부분 정렬	49,995,000	49,923,747	0.14%
이미 정렬된 데이터에서는 첫 순회(9,999회 비교)에서 교환이 없어 바로 종료되므로 O(N) 으로 줄어든다.
역순 데이터에서는 마지막 순회까지 교환이 발생하므로 이득이 전혀 없다.
부분 정렬 데이터에서도 이득이 0.14%뿐이다(5.3절 참조).
5. 입력 상태별 성능 비교
5.1 입력 데이터 생성 방법

무작위 원본 데이터 1개(N = 10,000)로부터 다음 세 가지를 만들었다. (시험 입력 준비 과정은 비교·이동 횟수에 포함하지 않았다.)

입력 상태	생성 방법	역전 쌍 개수
정렬	원본을 Key1 오름차순으로 사전 정렬	0
역순	정렬된 배열을 거꾸로 뒤집음	49,994,953
부분 정렬	정렬된 배열에서 서로 다른 두 위치를 무작위로 500번(전체의 5%) 교환	3,297,566

역순의 역전 쌍이 N(N-1)/2 = 49,995,000보다 47 적은 이유는 Key1 값이 같은 쌍(중복)이 있기 때문이다.

부분 정렬 데이터 설계와 AI 활용: 부분 정렬 데이터 생성법은 AI(Claude)에게 "정렬된 데이터에 소수의 무작위 교란을 가하는 방법, 구간만 섞는 방법, 일부 원소 위치를 교환하는 방법"의 장단점을 물어 조사하였다. 그중 "정렬된 데이터에서 일부 원소를 무작위로 교환"하는 방식은 교환 횟수 하나로 무질서 정도를 조절할 수 있고 재현이 쉬워서 선택하였다. 교환 횟수(5%)는 "대부분 정렬되어 있으나 확실히 흐트러진" 정도를 의도하여 정하였고, 무질서 정도는 역전 쌍 개수(약 330만, 역순의 약 6.6%)로 정량화하였다. AI가 제안한 코드를 그대로 쓰지 않고, 비교·이동 횟수 정의와 맞는지 직접 확인하며 구현하였다.

5.3 입력 상태가 알고리즘 성능에 미치는 영향

선택 정렬 — 비교 횟수는 모든 입력에서 49,995,000회로 완전히 동일하다. 입력이 정렬되어 있어도 이를 알 수 없고 매번 남은 구간 전체를 검사하기 때문이다. 이동 횟수만 입력에 따라 변한다. 정렬 데이터는 0회(최솟값이 항상 제자리라 교환 생략), 부분 정렬은 1,512회(교환 약 504번 = 어긋난 위치의 수에 비례), 역순은 15,075회(교환 약 5,025번 = 앞쪽 절반과 뒤쪽 절반을 맞바꾸는 약 N/2번), 무작위는 약 29,970회이다. 어떤 경우에도 N-1번 교환 이하이므로 이동 횟수는 항상 매우 적다.

버블 정렬(일반) — 비교 횟수는 역시 항상 49,995,000회로 고정이다. 그러나 이동 횟수는 3 × 역전 쌍 수이므로 입력에 따라 0(정렬) → 9,892,698(부분 정렬, 3 × 3,297,566) → 약 75,000,000(무작위) → 149,984,859(역순, 3 × 49,994,953)로 크게 변한다. 역순에서는 모든 비교가 곧 교환이 되어 가장 나쁘다.

버블 정렬(조기 종료) — 이동 횟수는 일반 버블과 같고 비교 횟수만 줄어든다. 효과는 입력 상태에 크게 의존한다.

정렬 데이터: 49,995,000 → 9,999 (사실상 O(N))
부분 정렬: 49,995,000 → 49,923,747 (0.14%만 감소). 약 500번만 어긋나 있어도, 앞쪽에 있어야 할 작은 값이 뒤쪽에 놓인 경우 한 순회에 한 칸씩만 앞으로 이동하므로 필요한 순회 수가 여전히 N에 가깝다. 즉 버블 정렬은 "큰 값이 앞쪽에 있는 경우"는 빨리 처리하지만 "작은 값이 뒤쪽에 있는 경우"는 매우 느리게 처리한다.
역순/무작위: 거의 효과 없음.

삽입 정렬 — 비교 횟수 ≈ 역전 쌍 수 + (N-1), 이동 횟수 = 역전 쌍 수 + 2(N-1)로, 입력의 무질서 정도(역전 쌍 수)에 정확히 비례한다. 실험으로 확인한 값:

입력	역전 쌍 수	비교 횟수	이동 횟수 (= 역전 쌍 + 19,998)
정렬	0	9,999	19,998
부분 정렬	3,297,566	3,307,565	3,317,564
무작위 (평균)	약 24,996,114	25,006,104	25,016,112
역순	49,994,953	49,994,999	50,014,951

정렬 데이터에서는 O(N), 부분 정렬에서는 선택·버블 대비 비교 횟수가 약 1/15, 역순에서는 O(N²)의 최악이 된다. 정렬에 가까운 데이터에서는 삽입 정렬이 압도적으로 유리하다. 정렬된 데이터에서도 이동이 19,998회 생기는 이유는, 제자리에 있더라도 매 원소마다 임시 변수 저장 1회와 최종 위치 대입 1회를 센 규칙 때문이다(과제의 이동 횟수 정의를 그대로 따른 결과).

6. 정렬 안정성 검증
6.1 검증 방법
각 데이터에 원래 입력 순서 번호(order) 를 부여한다 (정렬 기준에는 사용하지 않음).
정렬 후, 인접한 두 데이터의 Key1이 같은데 order가 거꾸로(앞 데이터의 order > 뒤 데이터의 order)인 경우를 순서 역전으로 센다.
순서 역전이 0이면 안정 정렬, 1건이라도 있으면 불안정 정렬로 판정한다. Key1이 같은 데이터는 정렬 후 인접해 있으므로, 인접 쌍만 검사해도 모든 동일 키 그룹의 상대 순서를 확인할 수 있다.
6.2 검증에 사용한 입력 데이터
검증 1 (과제 예시, 4개): (527,100) (527,200) (125,300) (892,400) — 정렬 전후의 실제 배열을 눈으로 확인한다.
검증 2 (중복 키 대량 데이터, 10,000개): 무작위 데이터는 Key1이 0~1,000,000 범위라서 중복이 드물기 때문에, Key1을 0~99로 제한하여 만들었다. Key1 값이 100개 그룹으로 나뉘어 각 그룹에 평균 100개의 동일 키 데이터가 존재한다 (중복 그룹 100개, 중복 데이터 10,000개).

프로그램 마지막의 "최종 요약"은 새로 만든 중복 키 데이터를 사용하므로 선택 정렬의 역전 횟수가 3,261로 위 표(3,254)와 조금 다르다. 판정 결과는 동일하다.

6.4 결과가 발생한 원인

선택 정렬 (불안정): 최솟값을 현재 위치와 멀리 떨어진 곳과 교환하기 때문이다. 4개 예시에서 첫 단계에 최솟값 (125,300)(인덱스 2)을 인덱스 0과 교환하면, 인덱스 0에 있던 (527,100)이 인덱스 2로 날아가 (527,200)의 뒤로 넘어간다. 배열은 (125,300) (527,200) (527,100) (892,400)가 되고, 같은 키 527의 순서가 뒤집힌다. 이후 어떤 단계에서도 이를 바로잡지 않는다(같은 키끼리는 서로 교환하지 않으므로).

버블 정렬 (안정): 인접한 두 데이터만 교환하고, 교환 조건이 a[j].key1 > a[j+1].key1 로 엄격한 부등호이다. 키가 같으면 교환하지 않으므로 같은 키의 두 데이터는 서로를 절대 추월하지 못한다. 조기 종료 조건은 교환이 없으면 멈출 뿐 교환 규칙을 바꾸지 않으므로 안정성에 영향이 없고, 실험에서도 역전 0건이었다.

삽입 정렬 (조건에 따라 다름): 다음 절에서 설명한다.

6.5 삽입 정렬에서 > 와 >= 의 차이

삽입 정렬은 current(삽입할 데이터)를 정렬된 앞부분의 뒤에서부터 비교하며, 이동 조건이 참이면 data[j]를 한 칸 뒤로 밀고 current는 더 앞으로 간다.

Case A (data[j].key1 > current.key1): 키가 같으면 이동하지 않고 멈춘다. current는 자신과 같은 키를 가진 앞 데이터들의 바로 뒤에 놓이므로, 원래 순서(앞 데이터가 먼저)가 유지된다 → 안정. 실험에서 순서 역전 0건.
Case B (data[j].key1 >= current.key1): 키가 같아도 계속 이동한다. current가 같은 키를 가진 앞 데이터들을 모두 추월하여 그 앞에 놓이므로, 같은 키 데이터의 순서가 정확히 뒤집힌다 → 불안정. 4개 예시에서 (527,200)이 (527,100)을 추월했고, 검증 2에서는 순서 역전이 9,900건이었다. 이 값은 100개 키 그룹 × (그룹 내 인접 쌍 99개) = 9,900으로, 모든 동일 키 그룹의 순서가 완전히 역순이 되었음을 보여준다.

성능 면에서는 두 방식의 차이가 거의 없다. 무작위 100회에서 >=는 평균 비교가 약 49회, 이동이 약 49회 많은 정도(0.0002% 수준)였다. 즉 >= 를 쓰면 같은 키를 불필요하게 넘나드느라 이동만 조금 늘어나고 안정성은 잃으므로, 이득 없이 손해만 있다. (키가 중복된 데이터가 많을수록 이 차이는 커진다.)

7. 결론
무작위 데이터에서 선택·버블 정렬의 비교 횟수는 모두 49,995,000회로 같고, 삽입 정렬은 그 절반(약 25,006,104회)이다.
조기 종료 버블 정렬은 무작위 데이터에서는 비교를 평균 0.02%만 줄이지만, 이미 정렬된 입력에서는 49,995,000회 → 9,999회로 극적으로 줄인다. 다만 역순이나 5% 부분 정렬(0.14% 감소)에서는 효과가 거의 없다.
선택 정렬은 입력 상태와 무관하게 비교 횟수가 같지만, 이동 횟수는 항상 가장 적다. 버블 정렬은 이동 횟수가 가장 많다(3 × 역전 쌍 수). 삽입 정렬은 비교·이동 횟수가 모두 역전 쌍 수에 비례하여, 정렬에 가까운 데이터일수록 매우 빠르다.
안정성: 선택 정렬은 불안정, 버블 정렬은 안정, 삽입 정렬은 > 일 때만 안정(>= 는 불안정)이다. 안정성은 "같은 키를 만났을 때 서로의 위치를 바꾸는가"에 의해 결정되며, 먼 거리 교환(선택 정렬)이나 같은 키까지 이동시키는 조건(>=)이 안정성을 깨뜨린다.
